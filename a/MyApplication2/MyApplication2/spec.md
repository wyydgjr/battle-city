游戏画面区域宽度 = 360vp（铺满）
游戏画面区域高度 = 530vp

原版地图：26列 × 26行 小格子
每个小格子尺寸 = 360 / 26 ≈ 13.85vp → 取整 14vp
实际游戏画面宽度 = 14 × 26 = 364vp → 微调为 13.85vp 精确适配

简化方案：
地图缩放到 360vp 宽度
地图高度 = 360vp（正方形）
地图上方留 170vp 用于显示敌方信息条
地图下方无间距

最终方案：
游戏Canvas区域：360vp × 530vp
地图在Canvas中居中绘制，尺寸360×360vp
地图上方区域(170vp)：敌方坦克剩余数量 + 关卡信息

## 4. 地图系统规格

### 4.1 格子系统

基础单位：小格子 (Tile)
原版规格：8×8 像素
鸿蒙适配：13.85×13.85 vp（取 14vp 精度）

大格子 = 2×2 小格子
地图 = 13×13 大格子 = 26×26 小格子

坐标系：
原点(0,0)在左上角
X轴向右，Y轴向下
小格子坐标：(col, row) 范围 [0,25]
大格子坐标：(bigCol, bigRow) 范围 [0,12]


### 4.2 地形类型

typescript
enum TileType {
EMPTY = 0, // 空地 - 可通行
BRICK = 1, // 砖墙 - 可被子弹摧毁
STEEL = 2, // 钢墙 - 普通子弹不可摧毁
WATER = 3, // 水面 - 坦克不可通行，子弹穿越
GRASS = 4, // 树丛 - 可通行，渲染在最上层
ICE = 5, // 冰面 - 可通行，会滑动
EAGLE = 6, // 基地（存活）
EAGLE_DEAD = 7 // 基地（被摧毁）
}


### 4.3 砖墙摧毁机制

砖墙由4个小块组成(2×2)：
┌──┬──┐
│TL│TR│ TL=左上 TR=右上
├──┼──┤ BL=左下 BR=右下
│BL│BR│
└──┴──┘

每小块可独立被摧毁
子弹击中时：
从上方击中 → 摧毁上排2块(TL+TR)
从下方击中 → 摧毁下排2块(BL+BR)
从左方击中 → 摧毁左列2块(TL+BL)
从右方击中 → 摧毁右列2块(TR+BR)

数据结构：每个大格子的砖墙用4位表示
bit0=TL, bit1=TR, bit2=BL, bit3=BR
0xF = 完整砖墙，0x0 = 完全摧毁


### 4.4 基地保护墙

基地位置：第12行第5-6大格（底部中央）
基地周围默认砖墙保护：

    ┌─┐
┌───┤ ├───┐
│砖│鹰│鹰│砖│
└───┤ ├───┘
└─┘
基地左右和上方有砖墙包围
下方开口（基地在地图最底部一行）

### 5.4 敌方 AI 行为

移动逻辑：

生成时随机选择一个方向
持续朝当前方向移动
遇到以下情况时换方向：
a. 碰到墙壁/边界 → 随机新方向
b. 碰到其他坦克 → 随机新方向
c. 移动了一定距离(随机2-8大格) → 30%概率换方向
方向选择权重：
朝玩家方向：30%概率
朝基地方向：20%概率
完全随机：50%概率
射击逻辑：

射击间隔：1.5-2.5秒（随机）
移动时也会射击
朝当前面朝方向射击
子弹速度见上表
生成逻辑：

每关共20辆敌方坦克
同时在场最多4辆
3个生成点轮流生成
生成间隔：至少1.5秒
生成点附近有玩家坦克时延迟生成
生成时播放闪烁出现动画（0.5秒）

### 5.5 坦克移动对齐

原版核心机制：坦克转向时必须对齐到半格

实现逻辑：
坦克要改变方向时：
如果新方向是水平（LEFT/RIGHT）：
将Y坐标对齐到最近的大格子边界
即 Y = Math.round(Y / tileWidth) * tileWidth

如果新方向是垂直（UP/DOWN）：
将X坐标对齐到最近的大格子边界
即 X = Math.round(X / tileWidth) * tileWidth
对齐后才允许转向和移动
这保证了坦克能精确通过1格宽的通道

### 13.2 渲染架构

渲染方式：Canvas + CanvasRenderingContext2D 逐帧绘制

渲染分层（从底到顶）：
层0 - 地面层：冰面、水面波纹
层1 - 地形层：砖墙、钢墙、基地
层2 - 实体层：坦克、子弹、爆炸
层3 - 遮挡层：树丛
层4 - UI层：敌方剩余、生命、关卡号

主循环：
requestAnimationFrame(callback)
目标帧率：60FPS
每帧执行：输入处理 → 逻辑更新 → 碰撞检测 → 渲染

精灵渲染：
使用素材图片绘制坦克、子弹、墙等
DrawImageRect 将素材中的精灵区域绘制到Canvas
帧动画：每隔N帧切换精灵图索引

素材使用：
已准备的素材文件放入 rawfile 目录
通过 $rawfile(‘xxx.png’) 加载
Image 对象缓存已加载的素材


### 13.3 碰撞检测

基于格子+像素混合碰撞检测：

坦克移动碰撞：
计算坦克移动后的新矩形区域
将矩形区域转换为格子坐标范围
检查这些格子是否为可通行
检查是否与其他坦克矩形重叠
子弹碰撞：
子弹前沿所在格子检查
子弹矩形与坦克矩形AABB检测
子弹与基地矩形检测
道具拾取：
坦克中心点是否在道具矩形内

## 15. 虚拟摇杆详细规格

类型：固定位置虚拟摇杆（非跟随手指型）

外圈：
半径：70vp
颜色：#FFFFFF 透明度30%
边框：2vp #FFFFFF 透明度50%
4个方向三角标记：▲▼◄► 透明度40%

内圈（摇杆头）：
半径：28vp
颜色：#FFFFFF 透明度70%
按下时：#4488FF 透明度90%

操作逻辑：

手指在摇杆区域按下 → 激活摇杆
手指移动 → 内圈跟随手指偏移（最大偏移=外圈半径-内圈半径=42vp）
根据偏移方向和距离确定：
方向：偏移角度对应的4方向（上下左右）
移动：偏移距离超过15vp死区才开始移动
手指抬起 → 内圈回弹到中心 → 坦克停止
发射按钮：
圆形
半径：50vp
正常态：#FF4444 透明度80%
按下态：#CC2222 透明度100% + 缩放0.95
中心图标：简化炮管图案或文字" FIRE"

多点触控：
摇杆和发射按钮可同时操作
使用不同 TouchEvent 的手指ID区分

## 17. 2P模式规格

2P模式在同一设备上：
玩家1：左侧摇杆 + 左侧发射按钮
玩家2：额外一组摇杆和发射按钮

2P控制布局：
┌────────────────────────────┐
│ 游戏画面 │
├────────────────────────────┤
│ ◎P1摇杆 🔴P1发射 🔴P2发射 ◎P2摇杆│
└────────────────────────────┘

P1摇杆中心：(70, 125)
P1发射按钮中心：(170, 125)
P2发射按钮中心：(190, 125)
P2摇杆中心：(290, 125)

2P规则：
玩家1和玩家2可以互相击毁（友军伤害开启）
各自独立生命和得分
任一玩家触碰道具都有效
两玩家都死亡才Game Over

## 18. 性能指标

目标帧率：60FPS (16.67ms/帧)
帧时间预算：
输入处理：< 1ms
逻辑更新：< 3ms
碰撞检测：< 2ms
Canvas渲染：< 8ms
音频处理：< 1ms
余量：1.67ms

优化策略：

对象池：Bullet、Explosion 复用
脏区域渲染：仅重绘变化的区域
地图缓存：不变的地形绘制到离屏Canvas缓存
精灵缓存：已加载的Image对象全局缓存
音频缓存：soundPool预加载所有音效
